# Monitor · QQ 群管理

版本 `0.1.1`，作者 Moonne。支持 AstrBot `>=4.29.1,<5` 的 OneBot v11（aiocqhttp），面向 SnowLuma 和 NapCat。

提供申请卡片、人工／自动审批、全群共用消歧编号、入群算术验证、成员记录、本群黑白名单和公共黑名单。

## 启用

1. 安装并重载插件，为机器人授予 QQ 群管理员权限，配置 AstrBot 模板文转图服务。
2. 在插件设置的“启用群组”下拉菜单中搜索群名或群号并多选。默认不启用任何群；保存并重载生效。
3. 在目标群发送 `/g on` 开启审批与验证。自动审批和黑名单自动拒绝均默认关闭。

AstrBot 的群准入、插件选择及会话插件禁用设置同样生效。总开关关闭后，已选群仍记录成员进退。
移出启用列表后不接收该群工作；重新列入时保留 JSON 中的开关设置，旧申请和旧验证不会恢复。

## 命令

方括号是占位参数，使用时替换。无效参数、权限不足、无目标或过期操作均静默。私聊及未选择的群不启用本插件。
AstrBot 管理员拥有最高命令权限；其余按群主、群管理员、成员分级。

| 命令 | 权限 | 作用 |
| --- | --- | --- |
| `/g`、`/g help` | 群成员 | 图片指令清单 |
| `/g on`、`/g off` | 群管理员及以上 | 同时开关申请处理和验证 |
| `/g y`、`/g n` | 群管理员及以上 | 同意／拒绝；多申请时刷新全群编号页 |
| `/g y [编号/all]`、`/g n [编号/all]` | 群管理员及以上 | 处理全群最新已展示列表 |
| `/g auto` | 群管理员及以上 | 切换普通申请自动批准 |
| `/g auto skip_ban` | 群主 | 独立切换黑名单自动拒绝 |
| `/g ban [QQ号] [理由]`、`/g rmb [QQ号]` | 群主 | 添加／撤销本群黑名单，不立即踢人 |
| `/g wl [QQ号] [备注]`、`/g rmwl [QQ号]` | 群主 | 添加／撤销本群白名单 |
| `/g pb [QQ号] [理由]` | 群主 | 添加本人公共黑名单记录 |
| `/g rmpb [QQ号]` | 原添加人 | 撤销本人公共记录；AstrBot 管理员可撤销全部 |
| `/g info [QQ号]` | 群管理员及以上 | 仅返回成员记录图片 |
| `/ans [整数答案]` | 对应待验证成员 | 回答本轮入群验证题 |

例如：`/g ban 123456789 多次广告`、`/g y 1`、`/ans 21`。理由／备注最多 1000 字符。

## 审批与验证

开启后依次应用：

1. 本群白名单始终优先，自动批准且免验证，即使命中本群或公共黑名单。
2. 命中黑名单且 skip_ban 开启，自动拒绝；否则转人工，即使 auto 开启。
3. 其余申请按 auto 自动批准或进入人工队列。

每条申请接管 30 分钟。多申请按从旧到新编号，任何管理员刷新都会替换全群列表。
`all` 只处理最新完整展示的列表；新到申请不自动加入，已处理项目不使其他编号移动。列表也保留 30 分钟，但不延长申请期限。

实际成员增加通知触发算术验证，包括无申请直接加入的情况。题目发送成功后限时 10 分钟；答错可重试，不延时。
白名单、群主／群管理员、AstrBot 管理员和机器人自身免验证。
题目发送失败不启动踢人期限，最多投递三次。到期再次确认群开关、成员角色、名单、是否仍在群和入群批次；移除不附带禁止再申请。

申请、消歧和验证均为临时缓存。关闭功能会取消本群旧待办；重载／重启清空全部待办，不恢复旧倒计时，不在启动时补踢。
审批／踢人结果未知时不自动重试，管理员可在 QQ 原生界面核实。
成员记录是已知的最早／最近入群、最近退群及已观察退群次数，不能补造安装前和离线期间的完整历史。

## 数据目录

通过 `StarTools.get_data_dir()` 定位，通常为：

```text
data/plugin_data/astrbot_plugin_group_manager/
├── db/
│   └── group_manager.sqlite3
└── settings/
    └── onebot%3AGroupMessage%3A12345.json
```

JSON 文件名是完整群 UMO 的百分号编码，避免 Windows 不支持冒号。同一 UMO 文件按机器人账号分别保存开关，数据库按平台实例、机器人和群隔离。
SQLite 只有三张表：`group_members`、`group_list_entries`、`public_blacklist_entries`。群设置、申请、编号和题目不建表。
本群名单每种类型保留当前／最近操作和撤销信息；公共名单按 QQ 和添加人保留记录。公共范围为同一数据库，各添加人分别撤销，全部撤销后才解除。
仅当前命中公共黑名单的对象允许查询其他群的成员汇总记录，不保存独立进退群事件表、历史批次表或审计表。

本版本不包含旧数据库迁移、数据导入或自动删除旧库。备份时停止插件取得一致副本，不手动删除 WAL/SHM。

## 日志与事件

临时事件追踪、每步数据流日志及独立文件写入线程已移除。常规异常、过载和结果未知警告使用 AstrBot 插件 logger，遵循宿主日志级别；异常详情脱敏并截断。
已有 log/monitor.log 属于旧诊断输出，保留原文件，当前版本不再写入。

监听采用 AstrBot 正式群事件 Handler，从 event.message_obj.raw_message 读取申请和通知。
普通加入和邀请加入均依赖 group_increase 通知触发验证，不要求先收到申请。AstrBot 4.29.1 应使用非空唤醒前缀，例如 `/`。
`/g y`、`/g n` 没有有效待办时静默；只处理插件接管的临时申请，不从 QQ 后台导入旧申请。重载或超过 30 分钟后需要重新发起测试申请。

SnowLuma 控制台出现 `pending group request not found` 时，应检查其申请匹配流程；v2.1.1 的该分支在事件派发前返回，插件无法处理尚未上报的申请。

## 图片和性能

统一使用 AstrBot Jinja2 模板文转图服务；资料会提交到配置的渲染端点。
时间为 `YYYY-MM-DD HH:mm:ss UTC+8`，页脚 `Create Time:` 靠右。北京时间 06:00–18:00 为白色主题，其余黑色；算术题始终白底黑字。

资料封面仅指顶部横幅。已停用将整张名片装扮预览当作封面的方式；已核对接口不保证提供用户自定义封面原图，运行时使用主题底图降级。头像以 URL 传递。
地区缺失显示未公开，账号等级以数字显示。申请方式、理由、审核状态和已知成员数据集中在记录卡片；黑白名单用底部小卡片，公共名单醒目提醒。
细分搜索／二维码来源未由已核对 SnowLuma v2.0.3 接口提供，按确认跳过，不猜测来源。

帮助面板默认使用原 default.png 的压缩 WebP 版本（约 25 KB）；可在“帮助面板背景地址”填写图片 URL，直接传址。
没有外部字体、脚本或公式库依赖。资料查询仅一次陌生人接口，短期缓存有容量和有效期限制。渲染最多两项并发，超时包含排队等待。
帮助／审批卡片失败可降级文字，`/g info` 失败仅记录日志，不混发文字。
消息顺序统一为 @目标用户、文字、图片。文字与 @ 之间留一个空格，图片前换行并独占最后一行；纯图片消息不添加 @。

## 开发

`main.py` 注册正式 g 指令组、ans、群事件和生命周期；`core/` 负责事件校验、业务编排与适配器调用；`models/` 每种纯数据模型独立文件；`utils/` 负责数据库基础工具和会话编码。
SQL 与 Jinja2 模板位于 `resource/`，隔离测试位于 `test/`。运行时不依赖浏览器，Playwright 仅用于本地合成预览。

后续功能统一使用 AstrBot 正式事件注册与适配器公开接口。OneBot 动作经宿主平台实例的 `get_client()` 入口调用；不自行创建 CQHttp 客户端、订阅底层事件或直连协议端。

详见本地开发文档 [DEV.md](docs/DEV.md)、[ASTRBOT.md](docs/ASTRBOT.md)、[SNOWLUMA.md](docs/SNOWLUMA.md)；docs 按现有仓库规则忽略。
