# Monitor · QQ 群管理

版本 `0.1.1`，作者 Moonne。支持 AstrBot `>=4.29.1,<5`，通过宿主适配器接入 OneBot v11（SnowLuma／NapCat）、QQ 官方 WebSocket 和 QQ 官方 Webhook。

提供申请卡片、人工／自动审批、全群共用消歧编号、入群算术验证、成员记录、本群黑白名单和公共黑名单。

## 平台接入

| 平台 | 成员标识 | 群选择 | 群管理要求 |
| --- | --- | --- | --- |
| OneBot v11 | QQ 号 | 群号或平台群 UMO | 机器人为群管理员；协议端上报申请与成员通知 |
| QQ 官方 WebSocket | Member OpenID | 完整平台群 UMO | 管理类机器人权限、群管理员及 GROUP_MEMBER_EVENT 事件订阅 |
| QQ 官方 Webhook | Member OpenID | 完整平台群 UMO | 同上；回调接收和验签由 AstrBot 管理 |

本轮适配 QQ 官方**群聊**，不将 QQ 频道、频道成员接口或私聊视为群管理。
QQ 官方不提供真实 QQ 号、QQ 等级、地址等原有资料；使用 OpenID 和可获取的昵称，其余字段按未公开／未知降级。
公共名单按身份域隔离：OneBot 保留 QQ 号共享；QQ 官方按同一 AppID 的 Member OpenID 匹配，不与 QQ 号或其他 AppID 自动关联。接口若返回不同 OpenID，不自动认定为同一用户；未猜测 Union OpenID 映射。

**宿主事件前置条件：**本地核对的 AstrBot 4.29.1 未向插件转发 QQ 官方的群申请、成员加入和退出事件。插件的官方命令与平台调用封装已完成，自动审批／验证还需要宿主投递这些事件。
已提供针对当前 4.29.1 源码的 [宿主事件补丁](resource/astrbot/qqofficial-group-events.patch)，并在临时副本验证两个接入方式；**未安装到本机宿主**。按用户要求，等待升级到 4.29.3 后重新核对，不预先认定新版本需要此补丁，也不在插件中接管底层连接或回调。

QQ 官方的群选项来自 AstrBot 已知群会话；若首次安装看不到群，先在该群 @机器人发送消息，再重载插件刷新下拉菜单。官方选项保存为 `平台ID:GroupMessage:群OpenID`，保留平台实例隔离。

## 启用

1. 安装并重载插件，为机器人授予 QQ 群管理员权限，配置 AstrBot 模板文转图服务。
2. 在插件设置的“启用群组”下拉菜单中搜索群名或群号并多选。默认不启用任何群；保存并重载生效。
3. 在目标群发送 `/group on` 开启审批与验证。自动审批和黑名单自动拒绝均默认关闭。

AstrBot 的群准入、插件选择及会话插件禁用设置同样生效。总开关关闭后，已选群仍记录成员进退。
移出启用列表后不接收该群工作；重新列入时保留 JSON 中的开关设置，旧申请和旧验证不会恢复。

## 命令

指令组全名为 `/group`，简写 `/g`；两者的子命令、权限和行为相同。

方括号是占位参数，使用时替换。无效参数、权限不足、无目标或过期操作均静默。私聊及未选择的群不启用本插件。
AstrBot 管理员拥有最高命令权限；其余按群主、群管理员、成员分级。

| 命令 | 权限 | 作用 |
| --- | --- | --- |
| `/group`、`/group help` | 群成员 | 图片指令清单 |
| `/group on`、`/group off` | 群管理员及以上 | 同时开关申请处理和验证 |
| `/group y`、`/group n` | 群管理员及以上 | 同意／拒绝；多申请时刷新全群编号页 |
| `/group y [编号/all]`、`/group n [编号/all]` | 群管理员及以上 | 处理全群最新已展示列表 |
| `/group auto` | 群管理员及以上 | 切换普通申请自动批准 |
| `/group auto skip_ban` | 群主 | 独立切换黑名单自动拒绝 |
| `/group ban [成员ID] [理由]`、`/group rmb [成员ID]` | 群主 | 添加／撤销本群黑名单，不立即踢人 |
| `/group wl [成员ID] [备注]`、`/group rmwl [成员ID]` | 群主 | 添加／撤销本群白名单 |
| `/group pb [成员ID] [理由]` | 群主 | 添加本人公共黑名单记录 |
| `/group rmpb [成员ID]` | 原添加人 | 撤销本人公共记录；AstrBot 管理员可撤销全部 |
| `/group info [成员ID]` | 群管理员及以上 | 仅返回成员记录图片 |
| `/ans [整数答案]` | 对应待验证成员 | 回答本轮入群验证题 |

成员ID在 OneBot 中为 QQ 号，在 QQ 官方中为该群成员的 Member OpenID。例如 OneBot：`/group ban 123456789 多次广告`；通用操作：`/group y 1`、`/ans 21`。理由／备注最多 1000 字符。

## 审批与验证

开启后依次应用：

1. 本群白名单始终优先，自动批准且免验证，即使命中本群或公共黑名单。
2. 命中黑名单且 skip_ban 开启，自动拒绝；否则转人工，即使 auto 开启。
3. 其余申请按 auto 自动批准或进入人工队列。

每条申请接管 30 分钟。多申请按从旧到新编号，任何管理员刷新都会替换全群列表。
`all` 只处理最新完整展示的列表；新到申请不自动加入，已处理项目不使其他编号移动。列表也保留 30 分钟，但不延长申请期限。

实际成员增加通知触发算术验证，包括无申请直接加入的情况。题目发送成功后限时 10 分钟；答错可重试，不延时。
白名单、群主／群管理员、AstrBot 管理员和机器人自身免验证。
题目发送失败不启动踢人期限，最多投递三次。到期再次确认群开关、成员角色、名单、是否仍在群和入群批次；移除不附带禁止再申请。

QQ 官方接入使用自定义 Markdown 卡片：待审批卡片提供“同意／拒绝”按钮；验证卡片提供三个不同答案，只有一个正确。题目仍由 AstrBot 渲染为白底公式图片，放在卡片正文最后一行。群聊自定义 Markdown 已公开开放，自定义按钮需要单独开通。
按钮采用官方指令按钮，点击后向机器人发送绑定当前申请／入群批次的指令，交给 AstrBot 正式消息 Handler；后台重新检查权限、群范围、有效期及是否已处理。审批不依赖消歧编号；其他成员点击无权按钮不会执行操作；AstrBot 管理员仍可操作。验证选项仅向目标成员开放操作，旧题／旧申请按钮失效。客户端不支持按钮时仍可使用手动命令。OneBot 保留原图片和命令方式。
官方卡片通过宿主管理客户端的公开 HTTP 接口发送；渲染图片 URL 必须能被 QQ 平台访问，插件直接传 URL，不额外下载图片。发送未获得明确消息 ID 时不启动验证期限。

申请、消歧和验证均为临时缓存。关闭功能会取消本群旧待办；重载／重启清空全部待办，不恢复旧倒计时，不在启动时补踢。
审批／踢人结果未知时不自动重试，管理员可在 QQ 原生界面核实。
成员记录是已知的最早／最近入群、最近退群及已观察退群次数，不能补造安装前和离线期间的完整历史。

## 数据目录

通过 `StarTools.get_data_dir()` 定位，通常为：

```text
data/plugin_data/astrbot_plugin_group_manager/
├── db/
│   └── group_manager.sqlite3
└── settings/
    └── onebot%3AGroupMessage%3A12345.json
```

JSON 文件名是完整群 UMO 的百分号编码，避免 Windows 不支持冒号。同一 UMO 文件按机器人账号分别保存开关，数据库按平台实例、机器人和群隔离。官方账号固定为 `qqofficial:AppID`，不使用消息中的临时 self_id。
SQLite 只有三张表：`group_members`、`group_list_entries`、`public_blacklist_entries`。群设置、申请、编号和题目不建表。
本群名单每种类型保留当前／最近操作和撤销信息；公共名单按 QQ 和添加人保留记录。公共范围为同一数据库，各添加人分别撤销，全部撤销后才解除。
仅当前命中公共黑名单的对象允许查询其他群的成员汇总记录，不保存独立进退群事件表、历史批次表或审计表。

本版本不包含旧数据库迁移、数据导入或自动删除旧库。备份时停止插件取得一致副本，不手动删除 WAL/SHM。

## 日志与事件

临时事件追踪、每步数据流日志及独立文件写入线程已移除。常规异常、过载和结果未知警告使用 AstrBot 插件 logger，遵循宿主日志级别；异常详情脱敏并截断。
已有 log/monitor.log 属于旧诊断输出，保留原文件，当前版本不再写入。

监听采用 AstrBot 正式群事件 Handler，从 event.message_obj.raw_message 读取申请和通知。
普通加入和邀请加入均依赖 group_increase 通知触发验证，不要求先收到申请。AstrBot 4.29.1 应使用非空唤醒前缀，例如 `/`。
`/group y`、`/group n` 没有有效待办时静默；只处理插件接管的临时申请，不从 QQ 后台导入旧申请。重载或超过 30 分钟后需要重新发起测试申请。

SnowLuma 控制台出现 `pending group request not found` 时，应检查其申请匹配流程；v2.1.1 的该分支在事件派发前返回，插件无法处理尚未上报的申请。

## 图片和性能

统一使用 AstrBot Jinja2 模板文转图服务；资料会提交到配置的渲染端点。
时间为 `YYYY-MM-DD HH:mm:ss UTC+8`，页脚 `Create Time:` 靠右。北京时间 06:00–18:00 为白色主题，其余黑色；算术题始终白底黑字。

资料封面仅指顶部横幅。已停用将整张名片装扮预览当作封面的方式；已核对接口不保证提供用户自定义封面原图，运行时使用主题底图降级。头像以 URL 传递。
地区缺失显示未公开，账号等级以数字显示。申请方式、理由、审核状态和已知成员数据集中在记录卡片；黑白名单用底部小卡片，公共名单醒目提醒。
细分搜索／二维码来源未由已核对 SnowLuma v2.0.3 接口提供，按确认跳过，不猜测来源。

帮助面板默认使用原 default.png 的压缩 WebP 版本（约 25 KB）；可在“帮助面板背景地址”填写图片 URL，直接传址。
没有外部字体、脚本或公式库依赖。资料查询仅一次陌生人接口，短期缓存有容量和有效期限制。渲染最多两项并发，超时包含排队等待。
帮助／审批卡片失败可降级文字，`/group info` 失败仅记录日志，不混发文字。
消息内容顺序统一为 @目标用户、文字、图片；官方按钮由客户端挂在消息底部。文字与 @ 之间留一个空格，图片前换行并独占最后一行；纯图片消息不添加 @。

## 开发

`main.py` 只保留正式指令／事件注册和生命周期；协议事件在 `core/adapter/` 转换为 `models/group_event.py` 的纯数据，再调用业务方法。

```text
core/
├── adapter/
│   ├── access.py       # AstrBot 会话权限
│   ├── handlers.py     # 事件过滤与入口转交
│   ├── registry.py     # 平台实现选择
│   ├── onebot.py       # OneBot 事件及动作
│   └── qqofficial.py   # QQ 官方两种传输共用群管实现
├── runtime.py          # 有界队列、任务、定时回收
├── commands.py         # 命令解析、权限和操作编排
├── approval.py         # 申请、审批与全群编号
├── members.py          # 成员同步与进退群记录
├── verification.py     # 算术验证与超时复核
├── cards.py            # 申请卡片与成员记录输出
├── rendering.py        # AstrBot Jinja2 模板视图
├── repository.py       # 名单及成员存取
└── settings.py         # 群设置 JSON
```

所有平台动作使用 AstrBot 提供的平台实例及其管理的客户端。QQ 官方新增群管动作使用该客户端公开的 SDK HTTP 传输，复用宿主认证；插件不创建客户端、保存凭据、订阅 SDK 底层事件或修改宿主全局对象。
SQL 与 Jinja2 模板位于 `resource/`；`models/` 每种数据类型独立文件且只存字段；`utils/` 提供数据库、时间与会话编码工具。隔离测试位于 `test/`，运行时不依赖浏览器。

详见本地开发文档 [DEV.md](docs/DEV.md)、[ASTRBOT.md](docs/ASTRBOT.md)、[SNOWLUMA.md](docs/SNOWLUMA.md)；docs 按现有仓库规则忽略。
